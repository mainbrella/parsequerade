Getting started

Quickstart

Configure the Worker, then read an app, an explicitly selected version, and an exact locale.

Status

Implemented reads This walkthrough uses working read routes. Deployments require operator configuration; asc.example.com and the IDs below are placeholders for your deployment and Apple resources. Mutation, report, and copy routes remain planned.

Prepare access

From the repository, install dependencies with npm ci. Obtain an Apple team API key with access to the app you want to read, and run the setup command with your issuer ID, key ID, private-key file, and allowed app ID:

Shell
npm run configure -- \
  --connection conn_example \
  --issuer-id YOUR_ISSUER_UUID \
  --key-id YOUR_KEY_ID \
  --private-key /path/to/AuthKey.p8 \
  --app-id YOUR_APP_ID

npm run dev

Repeat --app-id for several apps, or explicitly use --all-apps. Setup creates private .dev.vars, .parsequerade.secrets.json, and .parsequerade-client-key files and refuses to overwrite existing configuration. It makes no Apple calls or deployment. Set ASC_FACADE_KEY from the client-key file. Use http://localhost:8787/v1/connections/conn_example as the base for local reads.

For deployment, set your custom domain in wrangler.jsonc, run npm run check, and use npm run deploy -- --secrets-file .parsequerade.secrets.json. The Worker signs Apple JWTs internally; clients use only their facade key.

Requests use this connection-scoped base URL:

Shell
BASE='https://asc.example.com/v1/connections/conn_example'

1. List apps

Start with a bounded page. Narrow the list with a supported filter such as bundleId when you know it.

cURL
curl --fail-with-body "$BASE/apps?limit=50" \
  -H "Authorization: Bearer $ASC_FACADE_KEY"

curl --fail-with-body "$BASE/apps?bundleId=com.example.app&limit=50" \
  -H "Authorization: Bearer $ASC_FACADE_KEY"

The collection response contains plain objects in items and an opaque nextCursor. Select the intended app ID from the result; the service does not choose the first match for you.

2. Select a version

Use the app ID from the list, then choose the returned version ID that matches the platform and state you intend to read.

cURL
curl --fail-with-body \
  "$BASE/apps/1234567890/versions?platform=IOS&state=PREPARE_FOR_SUBMISSION" \
  -H "Authorization: Bearer $ASC_FACADE_KEY"

Replace 1234567890 with an app ID you received. The state filter is explicit; no draft-to-live fallback is implied. See List versions for its response fields.

3. Read an exact locale

Use the selected version ID and the exact locale you need. This example reads en-US from version_123.

cURL
curl --fail-with-body \
  "$BASE/apps/1234567890/versions/version_123/localizations/en-US" \
  -H "Authorization: Bearer $ASC_FACADE_KEY"

The route resolves that locale under the selected version and returns one flat object. If the exact locale does not exist, it returns 404 localization_not_found; request another locale or use the version-localizations collection to inspect available locales. It does not substitute the primary locale.

See Read a version localization for the response shape.
