Getting started

API conventions

The proposed facade uses flat JSON, explicit resource selection, bounded pages, and stable errors across its App Store Connect reads.

Proposed These conventions describe a planned service, not a running API. First release routes cover core app, app-info, version, and localization reads; additional reads have separate milestones.

Base URL and authentication

Resource routes are relative to https://asc.example.com/v1/connections/{connectionId}. Send a facade API key as Authorization: Bearer <facade-api-key>. The service would own Apple credentials and JWTs; clients never sign Apple JWTs or send Apple relationship envelopes.

A connection ID grants no access by itself. Check the caller’s connection and resource permissions on every request, including every cursor page. A missing or invalid facade key maps to 401 unauthorized; rejected configured Apple credentials map to 502 upstream_authentication_failed.

Resources and selection

  • Use explicit IDs for app, app-info, and version resources. Validate that each nested resource belongs to the selected parent app.
  • Use an exact locale key, such as en-US. A missing localization returns 404 localization_not_found; it does not fall back to another locale.
  • Choose platform and version state deliberately. The proposed adapter maps Apple’s state, appVersionState, and legacy appStoreState values; it does not select the first version or silently substitute a live one for a draft.
  • Only the fixed, documented fields on a route are returned or writable. Read access does not imply mutation support.

JSON shape

Responses use camelCase fields, string IDs, RFC 3339 timestamps, and Apple’s enum strings. Single-resource reads return flat objects. Collections use an items array and nextCursor; they do not expose Apple’s data, attributes, or relationships envelopes or recursively expand related resources.

Preserve the difference between an omitted field, null, an empty string, false, and 0. Unsupported or read-only fields are rejected instead of being silently dropped. A collection with no matches is 200 with items: []; an upstream failure is an error response.

Pagination

Collections default to 50 items per page. A route may set a lower or higher maximum within Apple’s endpoint limits. Pass a returned opaque nextCursor back as cursor with the same connection, route, filters, and ordering. Stop when nextCursor is null.

Cursors are planned to be signed, expiring, and bound to those request values. Each page is authorized again. A bounded request returns one page; internal traversal that exceeds page, time, or size limits returns an explicit error instead of a successful but truncated collection.

Query parameters

Routes accept only reviewed filters, sort keys, and selectors. Supported multi-value filters use comma-separated values where the endpoint documents them. Unknown parameters and unsupported combinations return 400 invalid_query. Filter and sort behavior is route-specific; it is not an arbitrary pass-through to Apple.

If a route explicitly supports a fields parameter, it selects response attributes only. It does not request Apple relationships or change resource selection. Do not send Apple’s include, filter[...], or pagination URL parameters directly.

Errors

Errors use one stable JSON envelope:

application/json
{
  "error": {
    "code": "validation_failed",
    "message": "One or more fields are invalid.",
    "requestId": "req_example",
    "retryable": false,
    "details": [
      {
        "field": "supportUrl",
        "code": "invalid_url",
        "message": "Provide a valid support URL."
      }
    ]
  }
}
HTTPCode or meaningUse
400invalid_queryMalformed input, unsupported query, selector, or cursor.
401unauthorizedMissing or invalid facade API key.
403forbidden / upstream_forbiddenCaller permission or configured Apple key does not allow the read.
404resource_not_foundResource or exact locale is absent or outside the caller’s scope.
409ConflictAmbiguous selection, duplicate resource, incompatible state, or idempotency conflict.
422validation_failedRecognized request has invalid fields or an Apple validation failure.
429rate_limitedFacade or Apple limit; respect Retry-After when present.
502–504Upstream failureRejected Apple credentials, invalid upstream payload, unavailable service, or timeout. These are not empty results.

Each response includes a request ID. Error details use facade field names and sanitized messages; credentials and private Apple response bodies are not returned.

Rollout

Initial delivery is core resource reads and selection, followed by observed mutations. Read-parity endpoints such as builds, users, and bundle IDs come later; reports and multi-step copy workflows are separate milestones. Each endpoint page labels its proposed stage.
